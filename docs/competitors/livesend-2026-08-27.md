# LiveSend competitor scan — 2026-08-27

Source URLs: [LiveSend homepage](https://www.livesend.io/), [FAQ](https://livesend.io/faq), [LiveSend vs Claude Artifacts](https://livesend.io/compare/vs-claude-artifacts), [Tiiny.host alternative](https://livesend.io/guides/tiiny-host-alternative).

## Why this matters

LiveSend is close enough to rtfx.pro that it should be treated as a direct category competitor, not just an adjacent static host. Their wedge is simple and commercially sharp: client-facing AI-generated HTML reports/proposals become branded, password-protected, tracked links with read receipts and inline updates.

## What LiveSend appears to lead with

- **Client-report/proposal use case first.** Agencies, consultants, B2B sales teams, founders.
- **No-deploy simplicity.** Drop/upload or paste HTML; get a link in ~30 seconds.
- **Branded URL path.** Pro links can be readable under a username/company path rather than a random id.
- **Password protection.** One-click password before open; 24h unlock cookie mentioned on public copy/FAQ.
- **Open/read analytics.** Opens, unique visitors, read time/duration, country, timestamp; optional viewer email/email gate appears in guides.
- **Owner notifications.** Email on first/every open is a homepage/FAQ selling point.
- **Inline editing after send.** Fix text/numbers without re-exporting or resending; changes are versioned.
- **Version history / rollback.** Guides say versions are kept automatically and the dashboard can roll back.
- **Collaborative review.** Homepage advertises text selection annotations, owner replies, resolve flow.
- **Pricing shape.** Public snippets show Free, Pro around $12/mo billed yearly, Team around $47/mo with seats.
- **Limits honestly stated.** 3MB Free / 6MB Pro HTML cap; no custom domain yet.

## rtfx.pro current counter-position

rtfx already has several stronger foundations:

- **Agent-native publishing is real.** Claude Code plugin, CLI, HTTP API, MCP, same authz path.
- **Identity-backed access exists.** Named users/workspaces/roles, not only public links with optional friction.
- **Versions/rollback exist.** Immutable artifact versions, current pointer rollback.
- **View log exists.** Stores viewer email, version, path, country, referrer, viewed_at.
- **Read-receipt email exists for named viewers.** `read_receipts` and `view_notice` mail path are implemented.
- **Share links exist.** Capability URLs are hashed, revocable, and can expire.
- **Governance is better.** Workspaces, roles, operator control plane, token scope/revocation.
- **Security story is deeper.** App/content host split, no injected analytics, token redaction, bundle filtering.

## Recommended next build batch

**Batch title:** LiveSend gap-close: client deliverable sharing + truthful positioning.

1. **Truth audit + positioning correction.** Verify all shipped access/share-link/read-receipt features, then remove stale “not shipped” statements where wrong.
2. **Artifact detail analytics polish.** Surface “who opened, when, how many times, which version, country/referrer” in a client-ready panel.
3. **Share-link control panel polish.** Create expiring/revocable links with clear copy, last-used status, and no secret re-display.
4. **Optional email gate spec.** If quick/safe, implement; otherwise leave as explicit next issue with schema/API design.
5. **Landing/docs copy pass.** Move the buyer-facing story toward reports/proposals/client previews while keeping rtfx's real differentiators: agent-native, identity access, governance, safety.

## Guardrails

- Do **not** copy LiveSend's wording or visual design.
- Do **not** claim password protection unless per-link passwords are actually built. Use “access-protected”, “named recipients”, “revocable/expiring share link”, or “optional email gate”.
- Do **not** weaken the existing identity-first model just to match password-link competitors.
- Keep competitor details in internal docs unless intentionally publishing a comparison page.
- Add tests for every public-copy claim changed by this batch.
